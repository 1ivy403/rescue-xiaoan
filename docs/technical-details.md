# 技术实现

## 输入

- Insta360 X4 的 360° 视频流或连续录制素材。
- 麦克风音频及其转写结果。
- RDK 上报的设备状态，以及操作员记录的机器狗任务状态和位置线索。

## 事件结构

系统以受困人员为单位组织事件，核心字段包括：

```json
{
  "target_id": "P-03",
  "location": "B1 东侧走廊",
  "observations": ["抬手回应", "腿部被构件遮挡"],
  "inferences": ["疑似意识清醒", "可能存在受压"],
  "environment_risks": ["上方构件松动", "通道积水"],
  "priority": "high",
  "confidence": 0.91,
  "recommended_action": "先进行结构稳定性确认，再建立撤离通道",
  "requires_human_confirmation": true
}
```

## 连续理解

系统不是只对单帧图片问答，而是持续接收抽帧画面、音频转写和设备状态。规则层负责合并同一目标的多次观察、标记信息冲突，并在证据不足时输出“待确认”而不是确定结论。

## 指挥中心输出

- 全局态势：发现人数、立即救援人数和状态未知人数。
- 人员队列：状态、原因、风险、定位和行动。
- 并行任务：救援组当前任务与机器狗当前侦察任务。
- 证据层：现场图、标注、音频线索和模型置信度。
- 详情卡：搜救难点、撤离建议和适用的补给建议。

## 控制方式

当前版本不通过 SDK 自动驱动机器狗。指挥中心输出“绕行”“补充第二视角”等任务，由现场操作员手动遥控执行；机械臂因硬件故障未接入。该边界保证现场演示与仓库代码保持一致。
